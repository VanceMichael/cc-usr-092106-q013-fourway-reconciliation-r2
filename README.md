# 票账货款四向核验

整理票据、台账、实物和付款的四向核验口径，并提供一个可运行的后端领域核心。

## 定位

基层检查面对一张同时带复印章和鲜章的发票时，真正要回答的是这张票是否对应
具体供货、台账记录、实物和付款，而不是印章看起来像不像真的。本仓库按这个
思路组织：系统只负责把四类依据对齐、把对不上的地方分类摆出来，**结论永远
由检查人员作出**。

## 模块

| 模块 | 职责 |
| --- | --- |
| `src/models.py` | 主体、采购关系、发票、随货同行单、台账、清点、付款、退货、折让、说明 |
| `src/quantities.py` | 数量值对象与箱盒换算，换算不上来不猜测 |
| `src/store.py` | 材料登记处：只追加不覆盖，发票更正必须递增版本号 |
| `src/loader.py` | 解析 JSON 资料包（契约见 `contracts/evidence.schema.json`） |
| `src/engine.py` | 匹配引擎：按采购关系提候选，四类差异分开呈现 |
| `src/permissions.py` | 检查方/供应商/药店的说明可见性与提交权限 |
| `src/review.py` | 案卷：人工决定、整改、从差异回到四类依据的溯源链 |

## 核验口径

- **匹配候选**只沿登记在册的采购关系提出，不跨关系撮合；候选是对应关系，
  不是结论。
- **四类差异分开呈现**：缺项（某一向没有材料）、数量差（票↔货、货↔账、
  账↔实、票↔款对不上）、日期冲突（发货早于开票、入库早于发货、付款早于
  开票、开票超出关系有效期）、主体不一致（无采购关系、单据或收付双方与
  登记主体不符）。
- **正常业务不误报**：分批送货按同行单合计；赊销在约定付款日前不报缺项；
  退货冲减数量、折让只减金额；合并付款与分批付款按发票-付款组件整体核对。
  只能部分解释的差异会注明已解释部分，留待人工定夺。
- **材料更正只追加新版本**：同版本号拒绝覆盖，旧版本永远可查；人工决定会
  冻结当时的证据版本快照。
- **自动匹配无权替代检查结论**：差异对象不含任何“违规”字段；供应商、药店
  账号无法调用结论接口，双方说明互相不可见。
- **完成一次检查后**，负责人可从任何差异回到四类原始依据、人工决定和后续
  整改；同一票据模板在不同门店反复出现会形成独立聚类线索。

## 示例数据

`fixtures/evidence/` 下有两个纯虚构案例：

- `case_normal.json`：分批送货、赊销、退货、折让、合并付款、发票更正，
  核验结果应为零线索；
- `case_anomalies.json`：四类差异各若干，外加同一票据模板跨门店串用。

`contracts/context.schema.json` 与 `fixtures/context.json` 为早期领域资料，
`src/context.py` 负责读取校验。所有示例均为虚构数据，不含真实个人信息、
账号或访问凭据。
