# 票账货款四向核验

面向医保检查的四向核验领域内核：把**发票与随货同行单（票）、进销存片段（账）、
现场箱盒清点（实）、银行付款摘要（款）**按采购关系组织成匹配候选，
差异按缺项、数量金额差、日期冲突、主体不一致四类分开呈现，
并完整保留材料版本、人工决定、整改与跨门店票据模板串并。

核心口径见 [`docs/核验口径.md`](docs/核验口径.md)。

## 模块

| 文件 | 职责 |
|---|---|
| `src/contracts.py` | 加载 `contracts/` 下 JSON Schema 并做结构校验（标准库实现，无第三方依赖） |
| `src/registry.py` | 材料只追加版本登记：更正只能追加更大 version，旧版本永久保留 |
| `src/matcher.py` | 四向匹配引擎：候选、四类差异、常见商业情形标注；**不输出违规结论** |
| `src/casework.py` | 人工决定、整改闭环、差异→四类依据的追溯、说明权限隔离、模板串并 |
| `src/context.py` | 领域上下文读取（基础资料） |

## 设计边界

- 引擎只产出 `reconciled / open / review` 候选与差异；**自动匹配无权替代检查结论**，
  violation / no_violation / needs_followup 只能由检查方人工登记。
- 分批送货、赊销、退货、折让、合并付款以 `explainable_pattern` 标注为可解释情形，
  候选状态为 `open`，不得被误报为必然违规。
- 材料覆盖缺口进 `coverage_warnings`，无归属的孤证进 `unmatched`，都不冒充差异。
- 复印章/鲜章字段只作票面事实记录，不参与任何计算。

## 契约

`contracts/`：信封 `envelope.schema.json` 及五类内容契约
（发票同行单、台账片段、现场清点、付款摘要、情况说明）+ 人工决定契约。

## 样例

- `fixtures/context.json`：领域上下文（基础事实）。
- `fixtures/case_2026_03_001.json`：一次完整检查的虚构案例，8 张发票覆盖
  核平、分批送货、折让+退货+合并付款、赊销、票货日期倒挂、票/货/账俱缺、
  个人账户收款、账实差、覆盖缺口、孤证、权限说明与模板跨店反复。

所有样例均为虚构数据，不含真实个人信息、账号或凭据。

## 本地校验

```bash
pip install -r requirements.txt
python -m pytest tests/
```

测试覆盖：契约校验、只追加版本、四类差异分类、五种商业情形不误报、
印章无关性、人工决定不可覆盖、证据快照陈旧提示、权限矩阵、模板聚类。
