# 票账货款四向核验口径

> 基层检查面对一张同时盖复印章和鲜章的发票时，要回答的问题不是"章像不像真的"，
> 而是这张票是否对应**具体供货、台账记录、实物和付款**。
> 印章字段（`has_copy_seal` / `has_original_seal`）在系统中只作票面事实留存，
> 不进入任何差异计算。

## 1. 四类原始依据

| 方向 | 材料 | 提交方 |
|---|---|---|
| 票 | 发票 + 随货同行单（`invoice_pack`，含退货凭证、折让行） | 供应商 |
| 账 | 进销存台账片段（`ledger_snippet`） | 药店 |
| 实 | 现场箱盒清点（`stock_count`） | 检查方 |
| 款 | 银行付款摘要（`payment_summary`，含分摊） | 药店 |

所有材料以信封提交，信封与内容均受 `contracts/` 下 JSON Schema 约束。

## 2. 只追加版本

- 同一 `material_id` 的更正必须以**更大 version 追加**，旧版本永久保留；
- 引擎默认只读最新版本；
- `submission_id` 全局唯一，禁止覆盖、禁止删除；
- 人工决定中的 `evidence_snapshot` 固定引用**作出决定那一刻**的提交版本；
  事后该材料出现新版本时，追溯链给出 `snapshot_stale` / `has_newer_version`
  提示，但**不回改结论**。

## 3. 匹配候选按采购关系组织

每张发票形成一个候选（`candidate`），携带：

- 采购关系：销方（供应商）、购方（连锁）、门店；
- 票、同行单、台账分录、清点批次、付款交易之间的对应关系；
- 候选状态：
  - `reconciled`：四向核平，无差异；
  - `open`：存在差异，但全部挂有常见商业情形标注，待人工确认；
  - `review`：存在未被常见情形解释的差异，需人工审查。

**自动匹配不产生"违规"字样。** 是否违规由检查方人工决定（violation /
no_violation / needs_followup），且只有检查方角色可以登记决定。

## 4. 差异固定四类、分开呈现

| 类别 | 含义 | 示例 kind |
|---|---|---|
| `missing` 缺项 | 某一方向完全缺失或找不到对应记录 | 未附同行单、无购入入账、无付款、清点未见批次 |
| `quantity` 数量金额差 | 能对上但数量/金额/箱盒不符 | 票货数量差、账实差、付款短款、行金额推算不符 |
| `date` 日期冲突 | 主体和数量都对，但时间逻辑异常 | 送货早于开票过容差、入账超出票货窗口、付款晚于账期 |
| `party` 主体不一致 | 名称、收款账户、供应商对不上 | 收款为个人账户、付款账户名非购方、台账供应商异名 |

材料覆盖缺口（某门店未交台账片段、未做现场清点）走 `coverage_warnings`，
**不冒充缺项差异**；不属于任何一张在查发票的孤证（台账多录入、付款指向
未知发票、库存存在未涉案批次）走 `unmatched` 单独列示。

容差：金额 0.01；送货早于开票 3 天内不提示；台账入账日期窗口 ±7 天。

## 5. 五种常见商业情形不得误报为必然违规

匹配到下列情形时，差异必须挂 `explainable_pattern`，候选状态为 `open`：

| 情形 | 标注 | 处理口径 |
|---|---|---|
| 分批送货 | `partial_delivery` | 同行单累计数量 < 开票数，按未交付缺口提示，不判虚开 |
| 赊销 | `credit_sale` | 账期内无付款提示"未到期"；逾期提示"待人工认定" |
| 退货 | `return` | 红字凭证与台账购退出账比对；缺出账只提示退货未记账 |
| 折让 | （行内字段） | `discount_amount` 体现在发票行金额内，应付自动核减 |
| 合并付款 | `merged_payment` | 一笔交易经 `allocations` 分摊到多张发票 |

此外，付款晚于账期（`late_payment`）、预付（`prepayment`）也按可解释情形标注。
**任何差异是否构成违规，一律等待人工决定。**

## 6. 账实推算口径

在本发票实际送货（及本票退货）的品种+批号范围内，且只统计清点日（含）之前：

```
应有库存 = 购入入账(purchase_in) − 购退出账(return_out) − 销售出账(sale_out)
```

现场清点按 `箱规 × 箱数 + 散量 = total_qty` 自洽校验，再与应有库存比较。
清点日后的销售、片段中其他采购关系的记录都不得串入本票推算。

## 7. 追溯与权限

- 从任何差异可经 `Casework.trace` 回到：四类依据的具体提交版本与版本历史、
  人工决定、理由、整改要求及整改状态变更历史；
- 供应商与药店**无权登记检查结论或整改**；
- 情况说明的可见性：
  - `internal`：仅检查方与提交方可见；
  - `shared_counterparty`：可向说明所涉票据的采购相对方公开；
  - 无关第三方（含其他供应商）不可见。

## 8. 票据模板串并

`template_id`（发票代码+版式特征）相同的发票按门店聚类。
同一销方的同一模板在两个及以上不同门店反复出现时，
`recurring_pattern=true`，支撑跨门店并案检查。

## 9. 虚构案例

`fixtures/case_2026_03_001.json` 为一次完整检查的虚构案例（8 张发票）：

- INV-0301：四向核平（票盖复印章+鲜章，结果与印章无关）；
- INV-0302：分两日送货 120+80，核平；
- INV-0305：行折让 100、退货 200、合并付款，核平；
- INV-0309：送货/入账早于开票 8 天，日期冲突；
- INV-0310：账期内未付款（赊销，open）；
- INV-0312：无同行单、无台账入账、款付个人账户（review）；
- INV-0313：60 天账期未到期、且该门店未交台账片段（open + 覆盖提示）；
- INV-0315：账实差 20、付款账户名与购方不一致（review）。

另含三条孤证、两份分权限说明，以及 TPL-88 模板在 ST-001/002/003 三店反复出现。
